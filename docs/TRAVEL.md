# 出游：让角色在微信和 QQ 聊天

本说明对应养鱼 0.2.0。扫码连接后，平台中新收到的允许范围内私聊交给这个角色回答，继续使用她的人设和记忆。

## 连接流程

1. 在「养鱼」角色卡片点「管理」，选择「出游」。
2. 在左侧选择微信或 QQ，点连接；右侧显示从平台取得的登录二维码。
3. 使用账号本人的手机扫码并确认。若微信要求数字验证码，在页面填写手机里显示的 4 至 12 位数字并手动提交。
4. 页面确认“已连接”后，角色聊天自动开启。向对应通道发送一条文字私聊即可交流。
5. 二维码过期或失效时点“刷新二维码”。刷新会创建新登录挑战，旧二维码不能继续确认这次连接。

二维码在本地使用 [qrcode](https://github.com/soldair/node-qrcode) 绘制，许可为 [MIT](https://github.com/soldair/node-qrcode/blob/master/license)，不交给第三方二维码图像服务。获取登录码及查询状态仍需连接对应平台的登录服务。

## 平台范围

| 平台 | 通道与前置条件 | 接收与回复范围 |
| --- | --- | --- |
| 微信 | 腾讯 ClawBot / iLink 官方机器人通道，按平台要求扫码授权 | 扫码微信用户与机器人的新文字私聊 |
| QQ | 已安装并配置的本机 NapCat，提供 WebUI 与 OneBot WebSocket | 原 QQ 配置 `ownerUid` / `allowedUids` 允许名单内的新文字私聊 |

微信协议参考 [Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)，养鱼直接适配该通道，不要求额外运行 OpenClaw。QQ 使用 [NapCatQQ](https://github.com/NapNeko/NapCatQQ) 的接口；NapCat 是独立第三方组件，安装与使用条件以其文档为准。

当前不接入群聊、图片、语音、文件或视频，不提供任意联系人广播。QQ 未配置允许名单时不会向所有人开放。扫码确认和手机验证码由账号本人完成，开发测试不会代替用户操作手机认证。

## QQ 服务与旧“小鱼”迁移

当前版本从本机已有 QQ 桥和 NapCat 配置中发现服务地址、授权及允许名单。默认适配已有安装，不搜索全盘，也不下载或重新安装 QQ / NapCat。

QQ 服务未运行且普通 QQ 没有占用时，插件可隐藏启动已验证存在的 Boot 可执行文件及配套 QQ、Hook 文件。它不调用会终止 QQ 的旧 `start-napcat.ps1`，不关闭正在运行的 QQ。普通 QQ 已打开而扫码服务不可用时，请按提示使用 NapCat 启动的 QQ 后重试。

旧 `dsh-qq-bridge` 与养鱼同时消费同一个 OneBot 服务会导致重复回复。迁移时应先备份旧配置，再停用旧桥的 DSH 加载项及 `qq-bridge/config.json` 中的 `enabled`。旧聊天、历史和 life 记忆文件可以保留，不需要因此关闭 life 或人设插件。养鱼发现旧桥重新启用时会暂停该 QQ 聊天。

一套 NapCat 实例只服务一个养鱼角色。该实例已登录时可直接显示并绑定此账号，不会为了二维码强行登出。多 QQ 并行需账号、工作目录和端口独立的实例；本版没有新增实例向导。

已有其他本机实例时，可在 `$DSH_HOME/storages/dsh-yangyu/qq-service.json` 私下配置 `default` 或按角色 ID 配置 `characters`，每项包含 `webUiUrl`、`webUiToken`、`wsUrl`、`accessToken`、`allowedUids`。服务地址只接受本机地址；自定义实例需自行启动。此文件含授权信息，不应分享或上传仓库。更改允许名单后请重新连接该角色。

## 人设、会话和记忆

- 同平台的同一账号同时只能连接一个角色，同一个角色可分别连接微信和 QQ。
- 会话按角色、平台及联系人保存；长期记忆仍属于角色，与该角色的 DSH 聊天共享。
- 回复沿用 DSH 已配置的默认模型。没有可用默认模型会显示错误；平台授权本身不提供模型额度。
- 出游模型仅有当前角色的记忆写入、召回工具。私聊内容不赋予电脑文件、终端、浏览器或其他外部操作权限。
- 角色记忆开关继续生效，平台连接不会改变它们；模型不保证自动保存每句话。
- 仅发送已经正常完成的最终回复，不发送模型中间步骤。

同一角色允许的不同联系人可能通过角色记忆产生连续相处信息。联系人会话分开，并不表示长期记忆也按联系人拆开，请据此选择 QQ 允许名单。

## 暂停、解除与数据

“暂停角色聊天”保留连接和授权，停止本地收取与回复，可以重新启用。“解除连接”移除本地授权和出游路由，保留角色人设与记忆。它不远程登出 QQ，也不撤销微信平台授权；需要时请本人在平台侧处理。

已确认授权保存在 DSH Home 的 `storages/dsh-yangyu/travel-private.json`，角色资料仍在同目录的 `state.json`。角色 JSON 导出不含授权。完整迁移需要在 DSH 停止写入后分别处理这些文件；授权文件是本地敏感资料，本版没有独立密码加密，不应分享或放入公开仓库。

临时二维码挑战只保存在内存。微信数字验证码用于本次状态确认，不写入角色人设或记忆。关闭 DSH 会结束当前二维码挑战，重开后可重新获取；已确认授权可尝试恢复连接。

0.2.0 已通过 80 项自动测试。在真实 DSH 中已验证“出游”界面、微信二维码显示与刷新（新旧挑战不同）。QQ 已通过已有 NapCat 登录会话绑定到养鱼角色，并完成一次真实私聊回复；对应原生模型会话正常结束、归属正确，工具列表只有该角色的记忆写入与召回。没有为测试强制退出 QQ，因此新的 QQ 扫码登录仍待本人操作验证。微信手机扫码、验证码及微信消息往返待本人连接后验证。基础角色记忆写入、跨会话召回与角色隔离已完成真实模型验证。
